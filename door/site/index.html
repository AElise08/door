How it works

  1. They text a number you authorized. Anyone not on your list gets one fixed reply and nothing else.
  2. You approve, or not. Every single question reaches you first, with a one-time code. Your approval is tied to the exact text of that question.
  3. An agent answers from a copy. A fresh container reads only the files you exported, with no network except the model, and then it is destroyed.
  4. They get the answer by text. If the filter spots something that looks like a secret, the reply is held for you instead.

What guests can and cannot do

They can

  • Ask questions about the repos you export
  • Get short answers by text
  • Cancel their own pending question

They cannot

  • Change anything in your project
  • See files you did not export
  • Get a shell, a terminal or your credentials
  • Add themselves, raise limits or approve anything

You stay in control

Your Mac stays closed

  • It only makes outbound connections
  • The Mac re-checks every request locally

Your money stays capped

  • You bring your own model API key
  • Limits per question, per guest per day, per month
  • Hard stop at 100% of your budget

Honest limits: this first version answers questions only. The reply filter is a smoke alarm, not a guarantee. The real protection is that secrets are never in the copy the agent reads. You need a Mac with Docker.

Questions

Do guests need an app?

No. They send a normal text message to the number you give them.

Can the agent edit my code?

No. This version is questions only. The agent reads a read-only export and nothing is written back.

What do you store?

Guest phone numbers, requests and replies for 30 days (then only metadata), and usage totals. Your code stays on your Mac, except the parts the agent reads to answer a question: those go to your model provider through your own API key.

What if someone fakes a phone number?

They still need your approval for every question, and the agent can only read what you exported inside a sandbox, within your budget.
